# 트러블슈팅

sim/콘솔 실행 중 자주 겪는 문제와 해결. 실행 절차 자체는 [`RUN.md`](../RUN.md) 참고.

---

## 콘솔 맵에 로봇이 안 뜸 / `/robot_state` Publisher count 0 — drive 모드 (가장 흔함)

**증상**: sim은 뜨고 로봇도 굴러가는데(cmd_vel) 콘솔(:8001) 맵에 로봇이 안 보인다.

**확인**
```bash
ros2 topic info /robot_state     # Publisher count: 0  (구독자만 있고 발행자 없음)
gz topic -l | grep robot_state   # gz 쪽에도 없음
```

**원인**: `scripts/sim/sim_slotcar3.launch.xml` 이 `upload_robot.launch.py` 에 `description_file:=urdf/pinky_slotcar.urdf.xacro` 를 넘기는데,
그 런치는 **`description_file` 을 안 읽는다**(죽은 인자, 파일도 존재하지 않음). 실제로는 `urdf/robot.urdf.xacro` 를 하드코딩하고
**`drive` 인자(`diffdrive` | `slotcar`, 기본 `diffdrive`)** 로만 분기한다.
기본 `diffdrive` 는 `libslotcar.so` 를 안 얹으므로 RMF `RobotState` 발행자가 없다 (diffdrive 는 `cmd_vel`/`odom` 만 냄).

**해결**: `sim_slotcar3.launch.xml` 의 upload include 에 `drive:=slotcar` 를 준다.
```xml
<include file="$(find-pkg-share pinky_description)/launch/upload_robot.launch.py">
    <arg name='use_sim_time' value='True'/>
    <arg name='is_sim' value='True'/>
    <arg name='drive' value='slotcar'/>
</include>
```
URDF 는 **그대로 핑키**(`robot.urdf.xacro` = 핑키 본체/메시)이고, 모션 플러그인만 diffdrive→slotcar 로 바뀌어
`libslotcar.so` 가 `/robot_state` 를 직접 발행한다(rclcpp, 브리지 불필요). 즉 "생김새는 핑키" + "/robot_state 발행" 동시 만족.

**참고**: `libEGL warning: ... driver (null)` 로그를 보고 GPU 문제로 오인하기 쉽다. 그 경고는 대개
Mesa→NVIDIA 폴백 노이즈일 뿐(카메라는 실제 초기화됨). 다른 환경에서 같은 런치가 잘 됐다면,
그 환경의 `pinky_description` 은 `drive` 기본값이 `slotcar` 였을 것.
